# 换机与开发环境恢复

本页说明如何在另一台电脑恢复源码开发。克隆公开仓库只会取得已经推送的提交，不会带走原电脑上的未提交修改、AI 对话、本地计划、截图或 EXE。同步尚未确认和完成前，不应把远端当作本机最新成果的备份。

## 安装与启动

1. 安装 Git 和 Node.js。源码运行要求 Node.js 22 或更高版本；构建 Windows x64 便携样机请使用 Node.js 24 x64。现有验证环境使用 Node.js 24.16.0、npm 11.13.0 和 Git 2.54.0.windows.1，其他版本仍需在目标设备验证。
2. 克隆仓库并进入目录：

   ```text
   git clone https://github.com/RongNianXin/Git-State-Compass.git
   cd Git-State-Compass
   git status --short --branch
   git rev-parse HEAD
   ```

   目的：确认进入正确仓库和分支。预期在 `main` 且没有本地修改；提交号应与最后一次同步回执一致。不同则先核对远端和同步记录，不覆盖现有文件。

3. 安装锁定依赖并检查：

   ```text
   npm ci
   npm test
   npm run web
   ```

   目的：按 `package-lock.json` 恢复构建工具，再验证分析和本机接口。预期自动测试全部通过，服务给出 `127.0.0.1` 的随机端口。打开显示的地址后，页面应处于“尚未读取仓库”。`npm ci` 需要联网取得 npm 依赖；不要复制其他电脑的 `node_modules` 作为跨系统安装方式。

4. 点击“选择文件夹”，只选择希望分析的本地仓库。文件夹弹窗目前仅支持 Windows；其他系统可手动输入路径，但尚未完成 macOS 整体验证。取消弹窗应保持原状态；切换路径后旧结论应清空。

关闭服务终端即可退出。若安装、测试或启动失败，提供命令、错误文字、操作系统和 Node.js/Git 版本；不要公开访问令牌、私人目录、代码或仓库内容。若页面状态不正确，附脱敏截图和所选目标。

## 构建便携样机

在 Windows x64 和 Node.js 24 x64 环境，先完成 `npm ci`，再运行：

```text
npm run build:portable
```

预期生成 `output/portable/Git-State-Compass.exe` 和 `SHA256SUMS.txt`。构建使用当前 Node.js 可执行文件和源码，不要把另一机器的旧 EXE 当作本次构建。EXE 启动后仍需要本机已安装 Git；不需要测试者安装 Node.js。构建产物未签名、未作为 Release 发布，不要为测试绕过系统安全警告。

详细操作、预期表现与异常反馈见[便携版人工测试](../M3便携版人工测试说明.md)。构建成功、接口测试通过和新设备人工体验是三个不同结论。

## 接着做什么

截至本次同步准备，规则引擎、真实本地 Git 读取、浏览器界面和 Windows 便携构建入口已存在。文件夹选择、外层目录有限查找、当前 worktree 与基线说明处于待人工反馈阶段。

后续先在目标电脑核对文件夹选择/取消、外层目录候选选择、分支与工作目录是否看得懂，再决定是否修改产品。尚未实现实时 GitHub PR 查询、完整 PR 堆叠图、最终独立桌面窗口或 macOS 构建。工具不会自动执行 Fetch、Commit、Merge、Rebase、Push 或创建 PR。

## 源码之外的材料

| 材料 | 换机处理 |
| --- | --- |
| `.planning/`、`.codex-manual-cache/` | 本地计划、历史和调度状态，禁止直接加入公开仓库。若要换机携带，单独确认私密备份方式；旧对话身份不自动成为新设备上的有效写者。 |
| `.migration-backup/`、本地工具建议 | 历史原件及机器相关信息，保留本地；需要时通过另行确认的私密渠道备份。 |
| `output/`、`.playwright-cli/` | 构建产物、截图和日志，可能含本机信息；不是公开源码依赖，不自动上传。新机器可以重新构建，但不能据此恢复旧测试现场。 |
| `node_modules/` | 可通过锁文件重新安装。离线迁移另行准备，不承诺断网可安装。 |
| GitHub/工具认证、Git 配置和公共工作流 | 在新设备单独安装或登录，不复制令牌、个人配置或其他项目控制面到本仓库。公共工作流不是产品运行依赖。 |

公开仓库保留源码、样例、测试、双语 README 和设计文档；私密备份是否实际完成应以单独的备份回执和恢复验证为准。
