# 新手任务流程（v0-core）

这些流程是解释和决策顺序，不是自动执行脚本。Git State Compass 当前只读取快照并给出下一步建议，不会替用户运行 Push、PR、Merge 或 Rebase。

## 1. 我想提交 PR

1. 先看当前在哪个分支。
2. 如果是 detached HEAD，先切换到命名分支。
3. 如果工作区有未提交内容，先检查差异并完成本地提交。
4. 确认当前分支确实比目标分支多出提交。
5. 确认 Base、目标 remote 和仓库唯一明确。
6. 如果远端还没有这个分支，Push 是一个需要单独确认的远端动作。
7. Push 后重新读取 Head，再单独决定创建 PR 还是更新已有 PR。

核心提醒：Push 和创建 PR 不是同一个动作；“代码已经在本地”也不等于“代码已经在远端”。

## 2. 我想合并 PR

1. 确认 PR 仍然开放，且 Head、Base 没有变化。
2. 检查是否为 Draft。
3. 检查 Checks、Review 和分支保护是否满足。
4. 如果有冲突，先处理冲突并重新验证。
5. 读取仓库允许的合并方式和团队约定。
6. 再比较 merge、squash、rebase 对历史的影响。
7. 合并属于远端写操作，工具只给建议，不替用户点击或执行。

核心提醒：Checks 通过不代表存在唯一正确的合并方式；合并方式会影响项目历史。

## 3. 我想把远端更新到本地

1. 先选择唯一的 remote 和 upstream。
2. 确认本地快照是新鲜的。
3. 如果工作区有未提交内容，先保护现场。
4. 先区分 Fetch、整合和修改工作树：它们不是同一个动作。
5. 如果本地落后，先 Fetch，再重新查看差异。
6. 如果本地和上游分叉，工具不会替用户猜 Merge 或 Rebase。
7. 重新采集快照后，再决定下一步。

核心提醒：Fetch 只更新本地的远端跟踪信息，不等于把远端代码合进当前分支。

## 状态词翻译

| 工具状态 | 人话 |
|---|---|
| `READY` | 事实足够，可以给出下一步建议，但不代表工具会自动执行 |
| `NEEDS_CHECK` | 还缺信息，先刷新或选择目标 |
| `BLOCKED` | 当前有风险，继续操作可能造成误判，应先处理阻断 |
| `requires_confirmation` | 这一步会影响远端或历史，需要单独确认 |
